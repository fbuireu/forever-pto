Consent management is built on `vanilla-cookieconsent`, but with the library's UI **disabled**: it runs headless (`autoShow: false`) as the consent state machine, while the banner and preferences dialog are the app's own React components styled like the rest of the design system.

## Composition

- `apps/web/src/ui/modules/shared/cookie-consent/CookieConsentClient.tsx` is a `dynamic(..., { ssr: false })` wrapper mounted in the root locale layout; consent state lives in the browser, so there is nothing to render on the server.
- `CookieConsent.tsx` initializes `CookieConsentLib.run(...)` once, renders the custom banner when no consent cookie exists yet, and otherwise renders `CookieConsentDialog` (the preferences modal, reopened via the `cc:showPreferences` window event, dispatched from the footer).
- `config/config.ts` holds `COOKIE_SECTIONS`, the typed catalog that drives the preferences UI. Description/expiry strings are i18n keys typed against the `cookies` namespace of the English catalog, so a missing translation is a type error.

## Categories and services

These categories are registered with the library:

- **necessary**: `enabled: true, readOnly: true`, and not consentable. Per `COOKIE_SECTIONS` this covers `user-country` (see [country detection](/how-it-works/country-detection/)), the library's own `cc_cookie`, and Stripe's `__stripe_mid`/`__stripe_sid` (set during [donation checkout](/how-it-works/premium/)). The `NEXT_LOCALE` and `premium-token` cookies are likewise functional, not tracking; see [cookies](/reference/cookies/).
- **analytics** is the only consent-gated category, with independently toggleable services:
  - `ga4` covers Google Analytics (`_ga*`, `_gid` cookie patterns).
  - `betterStack` covers Better Stack browser analytics (`_bs*` patterns).

  Each service declares its cookies with regex patterns, and `autoClear` deletes them when consent is withdrawn.

## Consent flow

Accepting or saving preferences calls `CookieConsentLib.acceptService(enabledServices, 'analytics')`, then:

- **Google Consent Mode**: `apps/web/src/ui/modules/tracking/Analytics.tsx` loads gtag with a default of everything `denied`. On consent changes the component updates `analytics_storage` via `gtag('consent', 'update', ...)` and fires a `page_view` when granted, so GA never tracks pre-consent.
- **Better Stack tracking**: `apps/web/src/ui/modules/tracking/BetterStackTracking.tsx` listens to the library's `cc:onConsent` / `cc:onChange` document events and only injects the tracking script when the analytics category is accepted (and a tracking token exists). It also `identifyUser`s premium users post-consent. See [observability](/how-it-works/observability/).

On a revisit, `onConsent` restores per-service state from `CookieConsentLib.getUserPreferences()` so the dialog reflects reality.

## What this means in practice

No analytics code runs until the user opts in; rejecting all is a first-class, equally prominent action. Everything the app strictly needs to function (locale, country, premium session, payment) is in the necessary bucket and never blocked by consent.

## This wiki has its own, and shares only the vocabulary

`docs.forever-pto.com` asks the same question with a separate implementation: `apps/docs/src/lib/analytics/consent.ts` drives the same `vanilla-cookieconsent` version through the library's own UI, in English and Spanish, and `apps/docs/src/components/Head.astro` emits the Consent Mode defaults before `gtag.js` loads. The `analytics` category and the `ga4` and `betterStack` service ids are the same strings on both sites, deliberately, so the two read as one policy.

What is not shared is the UI. The app's is React reading `next-intl` off its own message bundles, with a cookie table listing Stripe cookies the wiki never sets. What is also not shared is the Better Stack source: the wiki has its own, because the app's tag reports a `release` taken from `apps/web/package.json` and the docs package version never moves. Google Analytics **is** shared, one measurement id across both subdomains, so a session that starts in the wiki and ends in the planner is one session. See [ADR 0019](https://github.com/fbuireu/forever-pto/blob/main/adr/0019-the-wiki-measures-itself-with-its-own-consent-flow.md).
