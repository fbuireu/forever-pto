Two layers cooperate here: an infrastructure service that **fetches** holidays, and a pure domain engine (`apps/web/src/domain/calendar/`) that **computes** what to do with them. The engine has no framework or SDK imports, which is also what lets it run inside a [Web Worker](/how-it-works/calculation-worker/).

## Fetching holidays

`apps/web/src/infrastructure/services/holidays/getHolidays.ts` uses the `date-holidays` package. `dateHolidaysSource.observedHolidays` (`apps/web/src/infrastructure/services/holidays/source/dateHolidays.ts`) fetches the selected year **and the next one** in a single call (carryover months need next year's holidays too) and looks the country up twice, once bare and once with the region, stamping `location` onto the regional entries only. Raw entries are transformed by `holidayDTO.create` (`apps/web/src/application/dto/holiday/dto.ts`) into `HolidayDTO { id, name, date, variant, location, isInPlanningWindow }`, where `variant` is one of `HolidayVariant.NATIONAL | REGIONAL | CUSTOM`. Errors resolve to an empty array and a Better Stack log: the planner degrades instead of crashing.

User-created holidays get the `CUSTOM` variant; the [holidays store](/how-it-works/state-stores/) preserves them across refetches.

## Bridges

The engine's core concept is the **Bridge** (`apps/web/src/domain/calendar/types.ts`):

```ts
interface Bridge {
  startDate: Date;
  endDate: Date;
  ptoDaysNeeded: number;
  effectiveDays: number;
  efficiency: number; // effectiveDays / ptoDaysNeeded
  ptoDays: Date[];
}
```

A bridge is a block of PTO days that connects weekends and holidays into one continuous break. `efficiency` is the payoff ratio: how many effective days off you get per PTO day spent.

## Entry points

- `apps/web/src/domain/calendar/pipeline.ts`: `runPlanningPipeline` is the whole run, and the only place orchestration lives: it clears the calculation caches, derives the pseudo-Holidays and the budget, calls both planning functions and computes the Metrics. Its two callers, the Web Worker and the holidays store's own action, add transport and nothing else. It existed twice once, the copies drifted, and one Planning Window then produced two different plans depending on which path ran.
- `apps/web/src/domain/calendar/suggestions/generateSuggestions.ts`: takes the `PlanningCandidates` the pipeline already built (`findPlanningCandidates` in `apps/web/src/domain/calendar/utils/candidates.ts` runs `getAvailableWorkdays` and `findBridges`, both in `apps/web/src/domain/calendar/utils/helpers.ts`), caps the budget at the number of available workdays and hands off to `selectBridgesForStrategy`. Returns sorted `days`, the chosen `bridges` and the `strategy`.
- `apps/web/src/domain/calendar/suggestions/utils/selectors.ts`: the strategy dispatch. `STRATEGY_ORDERING` maps each `FilterStrategy` to an ordering of the bridges, and an unknown strategy falls back to grouped; `selectGreedily` then walks that order, skipping any bridge that would overspend the budget or reuse a date already taken.
- `apps/web/src/domain/calendar/alternatives/generateAlternatives.ts`: produces distinct alternative plans (default cap of 4, from the holidays store's `maxAlternatives`). It first excludes bridges overlapping the current suggestion, then cycles through seven different bridge orderings (by efficiency, span, PTO cost, month, inverse efficiency, a composite, and a deliberate pseudo-random `Math.sin` ordering) plus rotation on later passes, deduplicating candidate plans via `getCombinationKey`. This yields genuinely different plans rather than near-duplicates.
- `apps/web/src/domain/calendar/metrics/generateMetrics.ts`: computes the `Metrics` block shown in the summary: Long Weekends, Rest Blocks, Max Work Streak, average Efficiency, Bonus Days, quarterly and monthly distribution, Bridges used, total Effective Days, Longest Vacation, and more.

## Who calls this

The synchronous path (store actions `generateSuggestions` / `generateAlternatives`) dynamic-imports these functions, but the primary production path runs the whole pipeline off the main thread; see [calculation worker](/how-it-works/calculation-worker/).
