Source: `apps/web/src/ui/modules/core/animate/effects/`. Reusable motion behaviors that other components compose rather than reimplement. Both are client components built on Motion's `m.*` layer, so they need a `LazyMotionProvider` ancestor.

## MotionHighlight

`MotionHighlight` renders the animated background pill that follows the hovered or selected item. It is the workhorse behind `DropdownMenu` and `Sidebar` (`apps/web/src/ui/modules/core/animate/base/`) and `Tabs` (`apps/web/src/ui/modules/core/animate/components/Tabs.tsx`), any place where a highlight glides between siblings.

### Modes

**`mode='children'`** (default, as in `DropdownMenu`): each item renders its own absolutely-positioned background `m.div` sharing a `layoutId`, so Motion morphs the pill between items as the active one changes. Hover an item below and the pill travels with the pointer:

<MotionHighlightChildrenDemo client:visible />

**`mode='parent'`** (as in `Tabs` and `Sidebar`): a single `m.div` lives in the container and animates `top/left/width/height` to the measured bounds of the active item (recomputed on container scroll and on every render). Use it when items live in a scrollable or oddly-nested layout where per-item `layoutId` morphing misbehaves:

<MotionHighlightParentDemo client:visible />

### Items

Every caller in the app places `MotionHighlightItem` itself and gives each a `value`; `MotionHighlight` takes a `value` of its own when something outside drives the active item, as `Tabs` does. Pass `hover` and the active item follows the pointer, as in `DropdownMenu` and `Sidebar`.

### Key props

`hover` switches activation from click to pointer-enter; `transition` is required (`DropdownMenu` and `Sidebar` use a spring of `stiffness: 350, damping: 35`); `className` styles the pill itself while `containerClassName` (parent mode) styles the wrapper. Items take `value`, `className` and `activeClassName`, and expose `data-active`, `data-value` and `data-highlight` attributes for CSS hooks.

## AutoHeight

`AutoHeight` animates a container's height to match its content. It measures the inner content with a `ResizeObserver` (via `useAutoHeight` in `apps/web/src/ui/hooks/useAutoHeight.tsx`) and springs the outer `m.div` to the new height. It takes `deps` and a `transition`, and forwards the other Motion props of a `div`. `deps` forces a re-measure when content changes for reasons the observer cannot see:

<AutoHeightDemo client:visible />

`TabsContents` (`apps/web/src/ui/modules/core/animate/components/Tabs.tsx`) uses it so panels of different heights cross-fade without layout jumps, with a spring of `stiffness: 200, damping: 25`.

## Usage

```tsx
import { MotionHighlight, MotionHighlightItem } from '@ui/modules/core/animate/effects/MotionHighlight';
import { AutoHeight } from '@ui/modules/core/animate/effects/AutoHeight';

// Hover pill across items
<MotionHighlight hover className='rounded-lg bg-accent' transition={{ type: 'spring', stiffness: 350, damping: 35 }}>
  <MotionHighlightItem value='light'>
    <button type='button'>Light</button>
  </MotionHighlightItem>
  <MotionHighlightItem value='dark'>
    <button type='button'>Dark</button>
  </MotionHighlightItem>
</MotionHighlight>

// Animated container height, re-measured when `expanded` flips
<AutoHeight deps={[expanded]} transition={{ type: 'spring', stiffness: 300, damping: 30 }} className='overflow-hidden'>
  {expanded ? <LongContent /> : <ShortContent />}
</AutoHeight>
```

## Conventions

- Never hand-roll a moving highlight in a new component; compose `MotionHighlight` like `DropdownMenu`, `Sidebar` and `Tabs` do.
- The pill defaults to `bg-muted rounded-md`; pass `className` to restyle it (the app usually uses the accent with a 2px frame).
- Related: [animated components](/design-system/animation/components/), [animated icons](/design-system/animation/icons/).

## In the app

`MotionHighlight` is composed by `DropdownMenu.tsx`, `Sidebar.tsx` and `Tabs.tsx` and by nothing else; `AutoHeight` only by `Tabs.tsx`.
