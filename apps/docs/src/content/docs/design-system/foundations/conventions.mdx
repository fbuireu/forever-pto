The design system lives in `apps/web/src/ui/modules/core/`. The rules it follows are written once, in [`CODING_STANDARDS.md`](https://github.com/fbuireu/forever-pto/blob/main/CODING_STANDARDS.md) (`U11`, `U12` and `X1` among them, with the mechanical ones under *Tooling already enforces*), and `apps/web/src/ui/modules/core/AGENTS.md` is the folder's map. This page documents the mechanics behind them.

## CVA variants, exported where they exist

Four components use [CVA](https://cva.style) (`class-variance-authority`): `Button`, `Badge`, `InputGroup` and the sidebar. The two whose variants other code reuses export the CVA object **alongside the component**, `buttonVariants` and `badgeVariants`:

```tsx
export { Button, buttonVariants };
```

Reasons:

1. Other components can reuse the exact class recipe without importing the component (e.g. styling a link as a button).
2. `VariantProps<typeof buttonVariants>` gives consumers, including these docs, the variant union as a *type*. The demo wrappers here build exhaustive `Record<Variant, …>` maps from it, so renaming a variant in the app breaks `astro check` instead of letting the [Button page](/design-system/components/button/) drift.

A single short variant is a `cn()` call or a local record instead: `Banner` and the planner's `MetricCard` take a `colorScheme` key into a local `COLOR_SCHEMES` record.

## `data-slot` attributes

Every component (and each sub-component of compositions like Card and Form) stamps a `data-slot` attribute:

```tsx
<Comp data-slot='button' … />
```

These are CSS containment hooks: `apps/web/src/ui/styles/base/index.css` targets `[data-slot='button']`, `[data-slot='badge']`, `[data-slot='input']`, `[data-slot='textarea']` and `[data-slot='card']` with the shared transition block (80ms linear for transform/box-shadow, 120ms ease for colors) that powers the [hover choreography](/design-system/foundations/shadows/). Styling by slot instead of by class keeps the timing rules in one place.

## `asChild` via the local Slot

Polymorphism uses the `asChild` pattern, but the `Slot` is **local**: `apps/web/src/ui/modules/core/animate/base/Slot.tsx`, built on `mergeProps` from `@base-ui/react/merge-props`. It clones the single child, merging className, style, refs and handlers.

```tsx
<Button asChild>
  <Link href='/planner'>Open the planner</Link>
</Button>
```

Note the headless layer throughout core is **Base UI** (`@base-ui/react`). No Radix package is a direct dependency (`vaul` and `cmdk` bring one in transitively), and the accessibility primitives (Dialog, Popover, Tooltip, Menu, Accordion…) all come from `@base-ui/react/*`. A motion-aware sibling, `MotionSlot` (`apps/web/src/ui/modules/core/animate/primitives/animate/MotionSlot.tsx`), does the same job for `m.*` components.

## Named exports

Core exports by name, as the rest of the app does, and Biome fails a default export: a `dynamic()` loader picks the named export, and without barrels the import path is the only index.

## No business logic in core

Core components are presentational, and the contract suite holds them to it: no store access, no API calls, no data fetching, and no translation keys, since components accept strings and `useTranslations` lives in the feature modules that render them. The components that reach app code (`Combobox` with its DTO props, `RichLink` with the next-intl `Link`, `Toaster` with `next-themes`) are exactly the ones these docs cannot render live, so they are documented reference-only.

## `cn()`

Class merging goes through one helper, `apps/web/src/ui/utils/cn.ts`:

```ts
export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

`clsx` handles conditional composition, `tailwind-merge` resolves conflicting utilities (last one wins per property group), so `cn(buttonVariants({ variant }), className)` lets a caller's `className` override variant classes predictably. `U11` says when a received `className` goes through `cn()` and when a static class list stays a plain string, because `cn()` drops a class twMerge reads as a conflict.

## Client/server split

Nearly every core file is `'use client'`, because everything animated needs Motion's `m.*` components, which in turn require an ancestor `LazyMotionProvider` (`apps/web/src/ui/modules/core/animate/providers/LazyMotionProvider.tsx`). The server-safe set (no directive, no hooks) is the plain primitives: Badge, Banner, Bone, Button, Card, FlagIcon, Input, Label, RichLink, Separator, Textarea, plus the Slot. `U5` says when a file takes the directive.
