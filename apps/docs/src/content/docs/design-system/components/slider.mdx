## How it works

- **Value normalization is the whole point of the wrapper.** Base UI emits `number` for single-thumb sliders and `readonly number[]` for ranges; consumers always want a mutable `number[]`. The component wraps `onValueChange` so it always receives `number[]`, and `value` is an array too.
- `onValueChange` fires continuously while dragging.
- Anatomy: `Root > Control > Track` holding two framed segments, then the thumb. The handle is a 6px bar in the frame colour, taller than the track, and the track stops short of it on both sides: the accent fill (`slider-range`) ends 8px before the value's position and the panel rest (`slider-rest`), which carries a stop dot at its far end, starts 8px after it. Each segment has a round outer end and a 4px inner one, so the gap reads as a cut rather than a seam.
- The wrapper computes the value's percentage itself, with the same linear mapping Base UI uses to place the thumb, and pins each segment by both insets. At the minimum the fill's insets cross and it draws nothing, and at the maximum the rest does the same, so neither end needs a special case. The frame is an inset shadow rather than a border, because a border would leave 6px of segment standing where the width is zero.
- The handle narrows from 6px to 4px while it is dragged (`data-dragging`), which is the slider's whole press feedback: a 6px bar has no room for the hover lift the framed controls use, so it carries no `hit-area-stable`.

## Usage

```tsx
import { Slider } from '@ui/modules/core/primitives/Slider';

<Slider
  label='Carry-over months'
  value={[months]}
  min={1}
  max={12}
  step={1}
  onValueChange={([next]) => setMonths(next)}
/>
```

## Conventions

- **`label` is required.** It becomes the thumb's `aria-label`: a slider with no visible text label is unusable with a screen reader, so the type refuses to let one ship rather than leaving it to a review.
- The rest of the prop surface is a deliberate subset (`value`, `min`, `max`, `step` and `onValueChange`, all required, since every caller sets them); extend the interface in the source if you need more of Base UI's API rather than reaching for the primitive directly. There is no `id`: it would land on the wrapper `div` Base UI renders, so a `<label for>` pointing at it would name nothing, which is why `label` is required instead.

## Accessibility

- Base UI renders each thumb as `role='slider'` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`; the required `label` prop becomes the thumb's `aria-label`, which is why it is not optional.
- Keyboard: arrow keys move by `step`, Page Up and Page Down by a larger step, Home and End to the bounds. The visible bar is 6px wide but the thumb's box is 24 by 32px, so the target meets the 24px minimum; a press anywhere on the track moves the value there too, and `touch-none` stops the page from scrolling while dragging on touch screens.
- Focus lands on Base UI's hidden range input inside the thumb, so the focus outline hangs off the thumb's `:has(:focus-visible)` and is drawn around the bar itself, 2px out.
- `onValueChange` fires on every pixel of a drag, so debounce anything expensive in the callback.
