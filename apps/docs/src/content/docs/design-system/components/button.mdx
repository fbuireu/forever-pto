## States and composition

Hover lifts the button up-left (`translate -2px, -2px`) while the hard shadow grows; press does the inverse. The pointer hit-area stays stable during the movement thanks to the `hit-area-stable` utility; see [Hit-area stability](/design-system/foundations/hit-area-stable/).

## Usage

```tsx
import { Button } from '@ui/modules/core/primitives/Button';

<Button variant='accent' size='lg'>Plan my year</Button>

// Render as a link while keeping button styling
<Button asChild>
  <Link href='/planner'>Open the planner</Link>
</Button>
```

## Conventions

- The CVA object is exported alongside the component (`buttonVariants`) so other primitives can reuse the classes.
- `data-slot='button'` is set for CSS containment hooks (the shared transition block targets it).
- Icons inside get `pointer-events: none` and a default `size-4` automatically.

## Accessibility

- A native `<button>` unless `asChild` hands the classes to a child, in which case the child's semantics are what ships: an `<a>` stays a link, with a link's keyboard behaviour.
- Focus is visible through a 3px ring offset from the background (`focus-visible:ring-[3px]`), which is the one state the hover lift does not cover.
- `disabled` drops pointer events, the shadow and the lift, so a disabled button reads flat; it stays in the tab order as native buttons do not, so prefer `aria-disabled` plus a no-op handler when the button must remain reachable.
- Icons inside are `pointer-events: none` and sized `size-4`, but they are **not** hidden from assistive technology: an icon-only button needs an `aria-label`.

## In the app

The most-used primitive in the tree. Among others: the planner's `PlannerPanel.tsx` (apply an Alternative), the homepage `Hero.tsx` and `Navigation.tsx`, the sidebar's collapsible triggers in `Sidebar.tsx`, and the recovery actions in `ErrorContent.tsx`.
