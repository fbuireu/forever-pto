Source: `apps/web/src/ui/modules/core/animate/base/Drawer.tsx`. A thin skin over [vaul](https://vaul.emilkowal.ski)'s drawer: vaul handles the drag-to-dismiss gesture and slide animation itself (no Motion `m.*` here, so no `LazyMotionProvider` needed, which is the exception in `animate/base/`).

Exports: `Drawer`, `DrawerContent`, `DrawerTitle`. There is intentionally no `DrawerTrigger` export; open it with controlled state.

<DrawerDemo client:visible />

## How it works

- `Drawer` wraps `vaul`'s root with `shouldScaleBackground` fixed to `false` (the app's brutal layout should not zoom out behind the sheet). Every other vaul root prop (`open`, `modal`, `dismissible`, snap points…) passes through.
- `DrawerContent` renders the portal and the sheet itself, with no overlay, since the page behind stays usable: fixed to the bottom edge, `rounded-t-[14px]`, 3px frame border on top and sides, `bg-card`, capped at `max-h-[85dvh]`. A pill-shaped vaul `Handle` is always rendered above your content for drag affordance.
- `DrawerTitle` is visually hidden (`sr-only`) by default, and vaul warns when a drawer has no accessible title, so always include one and override the class only if you want it visible.

## Props

`Drawer` forwards vaul's root props; the ones the app sets:

`DrawerContent` takes vaul's content props and adds none.

## Usage

```tsx
import { Drawer, DrawerContent, DrawerTitle } from '@ui/modules/core/animate/base/Drawer';

const [snap, setSnap] = useState<number | string | null>(0.15);

<Drawer
  snapPoints={[0.15, 0.85]}
  activeSnapPoint={snap}
  setActiveSnapPoint={setSnap}
  modal={false}
  open
  dismissible={false}
>
  <DrawerContent role='region' className='h-[100dvh] max-h-none'>
    <DrawerTitle>Planner</DrawerTitle>
    <div className='px-4 pb-6'>…</div>
  </DrawerContent>
</Drawer>
```

The planner's management bar (`apps/web/src/ui/modules/pages/planner/ManagementBar.tsx`) is the only consumer: it renders inline on desktop and, on mobile (`useIsMobile`), a full-height Drawer (`h-[100dvh] max-h-none`) that rests at 15% and 85% of the viewport. For a modal flow use [Dialog](/design-system/components/dialog/).

## Conventions

- `data-slot` hooks: `drawer`, `drawer-portal`, `drawer-content`, `drawer-title`.
- Content sits at `z-51`, below dialogs (`z-200`) by design, and below every transient overlay (popover and menu at `z-210`, tooltip at `z-220`), so a field inside it can still open one.

## Accessibility

- vaul renders the sheet as `role='dialog'` with focus management, like Dialog, though the app's sheet is not modal and not dismissible. `DrawerTitle` is rendered `sr-only` by default and is what names the sheet, so always include one.
- The drag handle is decorative: the sheet moves between its snap points and never closes by dragging.
- `modal={false}` is what keeps the page behind the sheet reachable; the sheet scrolls inside itself when its content is taller than the cap.

## In the app

The mobile planner panel in `ManagementBar.tsx`, where the Alternative switcher, the PTO budget meters and the Legend share one sheet.
