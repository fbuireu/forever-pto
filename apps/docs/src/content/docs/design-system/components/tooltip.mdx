## How it works

- The popup scales `0.5 → 1` on a spring out of `origin-(--transform-origin)`. The bubble is `bg-primary` with a 3px frame border and the accent-tinted `shadow-brutal-3-accent`; the "arrow" is a 45°-rotated square that repositions per side via Base UI's `data-side` attribute.
- A `Tooltip` mounts no provider of its own. A `TooltipProvider` around a group makes its tooltips share hover-delay state, with a 200 ms delay; every caller of the app that needs one mounts it itself.
- `TooltipTrigger` supports `asChild`.
- `TooltipInfoTrigger` is a ready-made trigger: a `size-5` accent square with a mono "i", `cursor-help`, `hit-area-stable` and the standard hover lift. Drop it next to a stat label and pair it with a `TooltipContent`.

## Props

`Tooltip` and `TooltipProvider` forward Base UI's root and provider props and add none. `TooltipContent` passes Base UI's positioner props to the positioner and `className` to the popup; the app sets two of them:

## Usage

```tsx
import { Tooltip, TooltipContent, TooltipInfoTrigger, TooltipTrigger } from '@ui/modules/core/animate/base/Tooltip';

<Tooltip>
  <TooltipTrigger asChild>
    <Button variant='outline'>Efficiency</Button>
  </TooltipTrigger>
  <TooltipContent>Effective days gained per PTO day spent.</TooltipContent>
</Tooltip>

<Tooltip>
  <TooltipInfoTrigger aria-label='What Efficiency measures' />
  <TooltipContent>Shown on hover or focus.</TooltipContent>
</Tooltip>
```

Tooltips are hover/focus-only hints, so content must be non-essential.
 For click-to-open content use [Popover](/design-system/components/popover/).

## Conventions

- `data-slot` hooks (from the motion primitive): `tooltip`, `tooltip-trigger`, `tooltip-portal`, `tooltip-positioner`, `tooltip-popup`, `tooltip-arrow`.
- `TooltipInfoTrigger` carries `ml-auto`, since it sits at the end of a label row, and takes no `className`.

## Accessibility

- Base UI renders the bubble with `role='tooltip'` and points the trigger's `aria-describedby` at it, so the text is read as a description of the trigger. It opens on hover **and** on keyboard focus, and Escape dismisses it.
- A tooltip is never the only place for information: the trigger has to make sense without it, and touch screens cannot hover.
- `TooltipInfoTrigger` renders an `aria-hidden` "i", so its `aria-label` is required: the type refuses a trigger with no name, which would leave the tooltip text as the description of an unnamed button.
