Source: `apps/web/src/ui/modules/core/primitives/Input.tsx`. A styled native `<input>` on `bg-input` with `rounded-[8px]` and the 3px frame border. No variants: state is communicated entirely through the shadow,: hover adds the extra-small brutal shadow, focus the small one, and `aria-invalid` swaps the border to destructive with a destructive focus shadow.

## Usage

```tsx
import { Input } from '@ui/modules/core/primitives/Input';

<Input type='email' value={email} onChange={handleChange} />

<Input aria-invalid={Boolean(error)} />
```

## Conventions

- `data-slot='input'` for CSS containment hooks.
- Validation styling is driven by `aria-invalid`, not a prop, so set it from your form state so styling and accessibility stay in sync.
- `h-11` matches the default [Button](/design-system/components/button/) height, so inputs and buttons align in rows.
- Pair with [Label](/design-system/components/label/); for prefixes, suffixes and inline buttons use [InputGroup](/design-system/components/input-group/).
- A number the visitor types is not `type='number'`: that input reads the point as the only decimal mark whatever the language. Use `NumberInput` (`apps/web/src/ui/modules/core/primitives/NumberInput.tsx`), which draws this same field over Base UI's `NumberField` and reads the language's own separators.

## Accessibility

- A native `<input>`, so labelling is the caller's job: pair it with [Label](/design-system/components/label/) through `id` and `htmlFor`, or give it an `aria-label` when there is no visible caption.
- `aria-invalid` is the single source of truth for the error state, so the border a sighted user sees and the state a screen reader announces cannot disagree.
- Focus is shown by the shadow growing rather than by an outline, and the frame keeps a 3:1 contrast against both surfaces.
