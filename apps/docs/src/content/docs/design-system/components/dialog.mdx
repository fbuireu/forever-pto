## How it works

- `DialogContent` (an alias of the internal `DialogPopup`) renders the portal, backdrop and popup in one go: a centered `bg-card` panel with 3px frame border, `rounded-[14px]` and `shadow-brutal-xl`, capped at `sm:max-w-lg`.
- `DialogHeader` is left-aligned at every width: centred on phones, it would put a long description in the middle while the text under it stays on the left.
- The popup never outgrows the screen. It is capped at `100dvh` less a `2rem` gutter and scrolls inside itself, with `overscroll-contain` so reaching the end does not chain to the page. That is the only way to reach content past the fold, because Base UI locks the page's scroll while a modal is open; a caller adds no `max-h` or `overflow` of its own. The close button scrolls with the content, so a header row that runs under it keeps the room clear itself.
- The backdrop is a fixed vertical gradient of near-black ink with `backdrop-blur-[2px]`, at `z-200` together with the popup.
- The top-right X is a brutal mini-button with `hit-area-stable` and hover lift; Esc and backdrop click dismiss as well.
- The root is controlled through `open` and `onOpenChange`, as every modal in the app is; the motion layer gates the portal behind `AnimatePresence` with `keepMounted` so exit animations complete before unmount.

## Usage

```tsx
import { Dialog, DialogContent, DialogDescription, DialogFooter, DialogHeader, DialogTitle } from '@ui/modules/core/animate/base/Dialog';

<Button onClick={() => setOpen(true)}>Delete holiday</Button>
<Dialog open={open} onOpenChange={setOpen}>
  <DialogContent closeLabel='Close'>
    <DialogHeader>
      <DialogTitle>Delete holiday</DialogTitle>
      <DialogDescription>This action cannot be undone.</DialogDescription>
    </DialogHeader>
    <DialogFooter>…</DialogFooter>
  </DialogContent>
</Dialog>
```

For a bottom sheet use [Drawer](/design-system/components/drawer/); for non-modal anchored content use [Popover](/design-system/components/popover/).

## Conventions

- `DialogHeader` draws the standard 2px bottom hairline (frame color at 18% opacity); `DialogFooter` stacks buttons column-reverse on mobile, row-end on desktop.
- `DialogTitle` is `font-black` with tight tracking, matching the app's display type.
- Always include `DialogTitle` (and ideally `DialogDescription`) for accessible labelling; Base UI wires the aria attributes.

## Accessibility

- Base UI renders `role='dialog'` with `aria-modal`, traps focus inside while open, closes on Escape and returns focus to the trigger on close.
- `DialogTitle` becomes the `aria-labelledby` target and `DialogDescription` the `aria-describedby` one, which is why both should always be present, even visually hidden.
- The close button's only text is `closeLabel`, rendered `sr-only`; it is required and a translated string, since the component cannot translate.
