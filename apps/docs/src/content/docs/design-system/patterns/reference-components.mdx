Most core components are framework-clean and get live demos elsewhere in this section. The ones below are not: each depends on Next.js infrastructure, app-layer types or a stylesheet the docs site does not load. They are documented **reference-only**, so read the source at the paths given.

## RichLink

`apps/web/src/ui/modules/core/primitives/RichLink.tsx` is the locale-aware link. Internal links render through the `next-intl` navigation `Link`, so hrefs are automatically prefixed with the active locale; `external` switches to a plain `<a target='_blank' rel='noopener noreferrer'>`.

- **API**: `href`, `className` (defaults to `text-primary hover:underline`), `external`, `children`. Plus the `createRichLink({ href, options: { className, external } })` factory, which returns a chunk-rendering function for `next-intl` rich-text tags (`t.rich('key', { link: createRichLink({ href: '/legal/privacy-policy' }) })`).
- **Coupling**: `import { Link } from '@application/i18n/navigation'` (next-intl's locale router).

## Sonner (Toaster)

`apps/web/src/ui/modules/core/primitives/Sonner.tsx` is the toast host, a brutal-styled wrapper over `sonner`'s `Toaster`. Fixed settings: `position='bottom-center'`, `duration={5000}`, `closeButton`. Per-type classes (success, warning, error, info) restyle toasts through a `--toast-bg` variable onto the brand colors, with 3px frames and hard shadows; the close button gets the standard hover lift.

- **API**: one required prop, `closeLabel`, the translated name of the close button; fire toasts with `toast(...)` from `sonner` anywhere below it.
- **Coupling**: `import { useTheme } from 'next-themes'`, which reads the active theme to keep toasts in sync with dark mode.

## Combobox

`apps/web/src/ui/modules/core/primitives/Combobox.tsx` is the searchable select used for the country, region, strategy and month pickers. Composes `Popover` + `Command` (cmdk) + `Button` + `FlagIcon`, with an `AnimateIcon`-driven `ChevronUpDown` that animates on hover and while open.

- **API**: `options: { value, label, flag? }[]`, `value`, `onChange: (value) => void` (called with the chosen option's `value`, typed by the options), `className`, `placeholder` and `searchPlaceholder`, all required, plus the optional `notFoundText`, `disabled` and `id`. Options with a flag render a `FlagIcon` next to the label.
- **Coupling**: its `hasFlag` helper (`primitives/utils/helpers.ts`) type-imports `CountryDTO` and `RegionDTO` from `@application/dto/country/types` and `@application/dto/region/types`, which ties it to the app's DTO layer.
- **Sizing**: the list is as wide as the control it opens from (Base UI's `--anchor-width`, with a 200px floor) and no taller than the room under it (`--available-height`), so a full-width control in a dialog or the sidebar gets a full-width list that scrolls. When even that does not fit below, the list flips above the control; it never falls back to the side, where a 200px list would land inside a dialog.

## Sidebar

`apps/web/src/ui/modules/core/animate/base/Sidebar.tsx` is the app's sidebar, in the one configuration the planner uses: a left-hand inset rail that collapses to icons. The parts are `SidebarProvider`, `Sidebar`, `SidebarTrigger`, `SidebarInset`, header/footer/content/group parts, `SidebarMenu*` and the `useSidebar` hook. Open state persists in the <code>{SIDEBAR_COOKIE_NAME}</code> cookie (name imported from the real export, see also [cookies](/reference/cookies/)), toggles with Ctrl/Cmd+B, and the rail becomes a spring-animated drawer on mobile. Menu buttons share a [MotionHighlight](/design-system/animation/effects/) hover pill and grow tooltips when collapsed.

- **API**: `Sidebar` takes a required `landmarkLabel`, the translated name of the landmark, and has no `side`, `variant` or `collapsible` prop: the rail is always `data-variant='inset'`, on the left, and `data-collapsible='icon'` once collapsed, which is what the `group-data-[collapsible=icon]` and `peer-data-[variant=inset]` selectors of its children key on. `SidebarProvider` takes no prop beyond its children and starts expanded until the cookie says otherwise. `SidebarTrigger` takes a required `className` and `label`. `SidebarMenuButton` takes a required `tooltip` string, shown only while the rail is collapsed on desktop, and carries one look, the framed outline button.
- **Coupling**: `import { setCookie } from '@ui/utils/cookie'` (the `cookieStore` API plus `temporal-polyfill`) and `import { useIsMobile } from '@ui/hooks/useMobile'`, which are browser and app runtime dependencies rather than `next/*`, but enough to keep it out of the docs bundle.

## Form

`apps/web/src/ui/modules/core/primitives/Form.tsx` is the shadcn-style `react-hook-form` glue. `Form` is `FormProvider`; `FormField` wraps RHF's `Controller` and publishes the field name through context; `FormItem` mints an id; `FormLabel`, `FormControl` (a `Slot`), `FormDescription` and `FormMessage` consume both contexts to wire `htmlFor`, `aria-describedby` and `aria-invalid` automatically, with `FormMessage` rendering the field error. `FormDescription` registers itself with its `FormItem`, so `FormControl` names it in `aria-describedby` only while it is on the page; `FormHeading` is a `<p>` styled like the label, for a field with no single control to point a `<label>` at.

- **API**: `Form`, `FormField` (takes RHF `ControllerProps`: `control`, `name`, `render`), `FormItem`, `FormLabel`, `FormHeading`, `FormControl`, `FormDescription`, `FormMessage`.
- **Coupling**: `react-hook-form` (`Controller`, `FormProvider`, `useFormContext`, `useFormState`), a runtime dependency the docs site intentionally does not install.

## FlagIcon

`apps/web/src/ui/modules/core/primitives/FlagIcon.tsx` renders a country flag as `<span class='fi fi-{code} rounded-sm overflow-hidden shrink-0 inline-block' aria-hidden='true'>`. The component itself is dependency-free (only `cn()`), but the visuals come entirely from the `flag-icons` stylesheet.

- **API**: `code` (ISO country code, lowercase; returns `null` when empty), `className`.
- **Coupling**: requires the `flag-icons` CSS, which the app imports in `apps/web/src/ui/styles/vendor/index.css`. The docs stylesheet deliberately loads only the app's theme and utility layers, so flags would render as empty squares here.

## Conventions

- If you need one of these in a new surface, check the coupling first: `RichLink` and `Sonner` only work inside the Next app shell; `Combobox` follows the DTOs; `Form` follows RHF; `Sidebar` and `FlagIcon` follow browser APIs and vendor CSS.
- Everything else in `apps/web/src/ui/modules/core/` is framework-clean; see the live pages under
 [components](/design-system/components/overview/) and the animation section starting at [animated icons](/design-system/animation/icons/).
