## Biome

A single `biome.json` at the repo root lints and formats the whole workspace, `apps/docs/` included. Highlights:

- Formatter: 120-char lines, LF, tabs, double quotes, trailing commas everywhere, Biome's own defaults bar the line width. The config declares no `javascript.formatter` block at all, which is what keeps it identical to the sibling repos'.
- `assist.actions.source.organizeImports: on`, so import sorting is automated. Don't hand-sort.
- Recommended rules plus `suspicious.noConsole` as an **error** with no allowlist: no `console` at any level. Log through [`apps/web/src/infrastructure/clients/logging`](https://github.com/fbuireu/forever-pto/tree/main/apps/web/src/infrastructure/clients/logging) instead. The one exception is scoped in `overrides` rather than hidden in a suppression comment: the BetterStack client's own unconfigured warning, which has no logger left to call.
- `apps/docs/src/styles` is excluded from formatting, because it carries Tailwind directives; the app's own style layers are not excluded, since `css.parser.tailwindDirectives` handles them in place. `*.d.ts` and `*.astro` files are excluded from linting, because Biome parses only an Astro file's frontmatter, so every import used in the template body would read as unused. `astro check` covers those files instead.
- VCS integration is on (`useIgnoreFile`, default branch `main`), which is what powers the `--changed` script variants.

Run `pnpm format:changed` before pushing if you bypassed the hooks; `pnpm verify` is what CI and `pre-push` both run.

## Git hooks (husky)

Installed by the `prepare` script on `pnpm install`. Three hooks in `.husky/`:

| Hook | Runs | Purpose |
| --- | --- | --- |
| `pre-commit` | `pnpm lint-staged` | Format + lint staged files; run unit tests for staged test files |
| `commit-msg` | `pnpm exec commitlint --edit` | Enforce conventional commits (see [conventions](/contributing/conventions/)) |
| `pre-push` | `pnpm verify` | The full gate (`format:check`, `typecheck` across both packages, and the coverage run) before anything leaves your machine. It is the same command the CI Check job runs |

### lint-staged

The active config is [`.lintstagedrc.json`](https://github.com/fbuireu/forever-pto/blob/main/.lintstagedrc.json), and it does one thing: Biome formats and fixes every staged file it recognises, in both packages. Tests are deliberately not here, because `pre-push` runs the full `pnpm verify`, so a commit stays fast and nothing reaches the remote unverified.

## CI-side scanners

- **zizmor** (`.github/workflows/zizmor.yml`) — lints the GitHub Actions workflows themselves for security issues and reports to code scanning. This is why every action in the repo is SHA-pinned with `persist-credentials: false`; follow that pattern when touching workflows.
- **Codecov** — `ci.yml` uploads Vitest coverage (`coverage/lcov.info`) on every push/PR. See [testing](/contributing/testing/).
- **CodeQL** — code scanning runs from GitHub's repository-level default setup, not from a workflow in the tree. There is deliberately no `codeql.yml` here: the two cannot coexist, and the default setup is what every repo in the family uses.
- **Dependency Review** (`.github/workflows/dependency-review.yml`) — fails a PR that introduces dependencies with known vulnerabilities.

## Dependency management

Renovate (`.github/renovate.json`) pins everything (including action SHAs), runs twice a month and automerges patch/minor updates via labels that `renovate-auto-approve.yml` keys on. pnpm policy lives in `pnpm-workspace.yaml`: an `allowBuilds` whitelist for postinstall scripts, a minimum release age for new versions, and `patchedDependencies` for the boneyard-js patch.
