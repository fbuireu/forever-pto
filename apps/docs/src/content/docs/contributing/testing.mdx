## Unit tests (Vitest)

Configured in `apps/web/vitest.config.ts` with `resolve.tsconfigPaths: true`, so all the app's path aliases (`@ui`, `@domain`, …) work in tests without extra mapping.

- **Environment**: happy-dom.
- **Setup** (`vitest.setup.ts`): runs Testing Library's `cleanup` after each test.
- **Excluded from the runner**: the end-to-end specs (`apps/web/e2e/**/*.spec.ts`), generated bones, icon directories and i18n message JSON.
- **Coverage**: v8 provider over `apps/web/src/**/*.{ts,tsx}` (tests, `types.ts` files and generated code excluded), reported as text + lcov, with a floor of 85 on lines, functions, branches and statements. `ci.yml` runs `pnpm test:ut:coverage` and uploads `apps/web/coverage/lcov.info` to Codecov on every push and PR.

Run locally with `pnpm test:ut` (or `pnpm test:ut:coverage`). Both finish with the contract suite below.

## Contract suite

`tests/docs-consistency.test.ts` at the repository root holds the documents, the workflows and the code to the claims it can check. It runs with `pnpm test:docs`, as the second half of `pnpm test:ut`, and in `pre-push` through `verify:changed`. [How this wiki is built](/contributing/docs-site/#what-keeps-it-honest) says what it asserts about this site.

## End-to-end tests (Playwright)

Two independent suites:

### App suite, `apps/web/e2e/`

Configured in `apps/web/playwright.config.ts`. Specs mirror the app's route structure (`apps/web/e2e/[locale]/(app)/planner/planner.spec.ts`, `apps/web/e2e/api/health.spec.ts`, …), which makes it obvious which route a failing spec covers.

- `baseURL` comes from the `BASE_URL` env var; without it the config starts `pnpm dev` and targets `http://localhost:3000`.
- In CI these tests run **against the live per-PR preview deployment**, authenticating through Cloudflare Access with a service token (`CF_ACCESS_CLIENT_ID`/`CF_ACCESS_CLIENT_SECRET`). Every spec takes `test` and `expect` from `apps/web/e2e/fixtures.ts`, which adds the token as `CF-Access-Client-Id`/`CF-Access-Client-Secret` to the requests whose origin is the preview's and to the `request` fixture, and to nothing a third party serves: `extraHTTPHeaders` in the config would send it to Stripe and Tag Manager too, so no config sets it. See [environments](/infra/environments/).
- Every spec runs in two projects, `chromium` (Desktop Chrome) and `webkit` (Desktop Safari), in CI and locally alike. CI adds two retries.

### Docs suite, `apps/docs/e2e/`

Configured in `apps/docs/playwright.config.ts`: every spec in `apps/docs/e2e/` runs against the built site through `astro preview` (`webServer` block), in the same two projects, `chromium` and `webkit`, so the site has to be built first. The `@smoke` cases in `smoke.spec.ts` also run against the deployed site after a production deploy. The suite runs in `.github/workflows/docs.yml` after the build.

## File conventions

| Kind | Pattern | Location |
| --- | --- | --- |
| Unit test | `*.test.ts` / `*.test.tsx` | Colocated next to the source file it tests, `apps/web/e2e/previewAccess.test.ts` included |
| E2E test | `*.spec.ts` | Only in `apps/web/e2e/`, mirroring routes, or `apps/docs/e2e/`, by topic |

The split is `T6` in [`CODING_STANDARDS.md`](https://github.com/fbuireu/forever-pto/blob/main/CODING_STANDARDS.md), and the tooling relies on it: the Vitest runner excludes the specs, Playwright matches `*.spec.ts` alone, and `test:ut:changed`, which `pre-push` runs through `verify:changed`, relies on the colocation to find the tests a change affects (see [tooling](/contributing/tooling/)).
