## Commits

Commit messages follow **conventional commits**, enforced locally by commitlint (`commitlint.config.ts`, extending `@commitlint/config-conventional`, with the header capped at 130 characters) through the husky `commit-msg` hook, and on the pull request title by `commit-message.yml`.

PRs are **squash-merged**, so the **PR title becomes the commit that lands on `main`**, and that title is what semantic-release (each package's `.releaserc.json`) analyzes. Get the type right on the PR title, not just on intermediate commits:

| PR title type | Release effect |
| --- | --- |
| `feat: …` | Minor version bump and changelog entry |
| `fix: …` / `perf: …` | Patch version bump and changelog entry |
| `feat!: …` or a `BREAKING CHANGE:` footer | Major version bump |
| `docs: …`, `chore: …`, `ci: …`, `refactor: …`, `test: …` | **No release** |

Each package versions itself, and a commit is attributed to whichever package its paths fall under ([releases](/infra/release/)). The rules that follow:

- **One package per pull request.** The repo squash-merges, so a PR touching both `apps/web` and `apps/docs` lands in both changelogs.
- **The title describes the package it touches.** A `fix:` on a wiki-only PR releases the wiki, not the app.
- **A change confined to the repo root releases nothing**: `.github/`, `biome.json`, `docs/adr/`, `tests/`, the root manifest.

semantic-release writes its own release commit as `chore(web): release x.y.z [skip ci]` for the app and `chore(docs): release x.y.z [skip ci]` for this site; commitlint lets it through.

## Code conventions

How code here is written is [`CODING_STANDARDS.md`](https://github.com/fbuireu/forever-pto/blob/main/CODING_STANDARDS.md), the file a review holds a diff to: each rule has an id (`D10`, `U12`, `L2`), is marked **hard** or **judgement**, and a finding cites it by that id. It opens with what Biome, the type checkers and the contract suite already enforce.

- **An `AGENTS.md` per folder.** Significant directories carry an `AGENTS.md` with the folder's map, the couplings a change there has to carry ("if you change X, update Y"), its runtime gotchas and its guardrails. Read it before modifying a folder; update it in the same commit when what it describes changes. The convention is declared in the root `AGENTS.md`. `GLOSSARY.md` is the domain glossary and lives at the repo root only; never create a nested one.

## Formatting

Formatting is not a convention you follow by hand: Biome formats staged files on every commit. See [tooling](/contributing/tooling/) for the hook chain and [testing](/contributing/testing/) for test-file conventions.
