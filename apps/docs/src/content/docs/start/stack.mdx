## Runtime

| Technology | Role | Why |
| --- | --- | --- |
| Next.js (App Router) | Framework | Server Components, prerendered per locale through `generateStaticParams`; Cache Components are deliberately off, see [caching](/architecture/caching/) |
| React | UI runtime | Required by Next; concurrent features (`use`, transitions) are used throughout |
| TypeScript | Language | `strict: true`; typed boundaries between layers are load-bearing, and the wiki's demos rely on them to catch drift |
| Tailwind CSS | Styling | CSS-first configuration with no `tailwind.config` file; the theme lives in CSS under `apps/web/src/ui/styles/` |
| Base UI | Headless primitives | Accessible behavior (tooltips, popovers, dialogs) without imposed styling, so the neo-brutalist skin stays in our CSS |
| Motion | Animation | `LazyMotion` keeps the animation runtime out of the initial bundle; see the design-system animation pages |
| Zustand | Client state | One small store per concern (`filters`, `holidays`, `location`, `premium`, `ui`), persisted where it must survive a reload, read through `useShallow` selectors |
| Effect | Server flows | Typed errors and dependency injection for the payment, Premium session and contact flows: the services are declared in `apps/web/src/infrastructure/` and composed by the use cases in `apps/web/src/application/use-cases/` (see [Effect layers](/architecture/effect-layers/)) |
| next-intl | i18n | Locale routing plus namespaced messages for the locales in `apps/web/src/ui/i18n/messages/` |
| boneyard-js | Loading skeletons | Generates skeleton components from real rendered output into `apps/web/src/ui/modules/bones` instead of hand-maintaining them |
| driver.js | Onboarding | Lightweight product-tour overlay with no framework coupling |

## Services

| Technology | Role | Why |
| --- | --- | --- |
| Turso | Database | libSQL at the edge, giving low-latency reads from a Worker without managing a server |
| Stripe | Payments | The one-time Donation that unlocks Premium; its webhook is handled in `apps/web/src/app/api/webhooks/stripe/` |
| Resend | Email | The contact-form notification, rendered with a react-email template |
| OpenNext + Cloudflare Workers | Hosting | Runs the Next.js app on Workers with an R2-backed incremental cache (`apps/web/open-next.config.ts`); see [environments](/infra/environments/) |

## Tooling

| Technology | Role | Why |
| --- | --- | --- |
| Biome | Lint + format | One fast tool instead of ESLint + Prettier; single config at the repo root covers app and docs |
| Vitest | Unit tests | Vite-native, resolves the TypeScript path aliases, runs in a happy-dom environment |
| Playwright | E2E tests | Chromium and WebKit: against `next dev` locally, against the preview of each pull request that changes the app, and, for the `@smoke` cases, against production after each deploy |
| semantic-release | Releases | Versions, changelog and GitHub releases derived from conventional commits; see [conventions](/contributing/conventions/) |

[Tooling](/contributing/tooling/) and [testing](/contributing/testing/) go into more detail on these.
