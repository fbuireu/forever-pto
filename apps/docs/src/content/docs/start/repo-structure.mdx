The repository is a pnpm workspace whose packages are the Next.js app and this wiki, both under `apps/` (the glob `apps/*` in `pnpm-workspace.yaml`). The root is the workspace root and nothing else: `forever-pto-monorepo`, private, `0.0.0`, with no dependencies of its own.

```
forever-pto/
├── apps/
│   ├── web/              # the planner (forever-pto-web)
│   │   ├── src/          # app source, layered (see below)
│   │   ├── e2e/          # Playwright specs mirroring the app routes
│   │   ├── wrangler.toml
│   │   ├── open-next.config.ts
│   │   └── next.config.ts
│   └── docs/             # this wiki (forever-pto-docs), Astro Starlight
├── docs/adr/             # architecture decision records
├── tests/                # docs-consistency, asserting repo-wide contracts
├── patches/              # patchedDependencies, applied by pnpm at install time
├── .github/workflows/    # CI/CD pipelines
└── biome.json            # lint and format, shared by both packages
```

There is no `packages/` tier; one is added the day a real shared package exists ([ADR 0010](https://github.com/fbuireu/forever-pto/blob/main/docs/adr/0010-apps-web-and-apps-docs-monorepo-layout.md)).

## `apps/web/src/` layers

Each directory has an `AGENTS.md` with its map and gotchas, the root `CODING_STANDARDS.md` holds the rules a review applies, and the [architecture overview](/architecture/overview/) covers the dependency direction between the layers.

| Directory | Role |
| --- | --- |
| `apps/web/src/app/` | Next.js App Router routes: `[locale]` pages and `api/` route handlers |
| `apps/web/src/application/` | Use-cases, DTOs and Zustand stores: orchestration between UI and domain |
| `apps/web/src/domain/` | Pure business logic: the calendar suggestion engine, payment domain events |
| `apps/web/src/infrastructure/` | External-world adapters: DB and API clients, services, i18n config, proxy helpers |
| `apps/web/src/ui/` | Components, hooks, styles, adapters to the app's own endpoints, utils and the i18n message catalogs |
| `apps/web/src/middleware.ts` | The [proxy](/architecture/proxy/), kept at the `middleware` file name so it stays on the edge runtime: Markdown rewrite, payment-confirmation guard, locale routing and cookie, Country detection |

## `apps/web/e2e/`

End-to-end Playwright specs (`*.spec.ts`) whose folders mirror the app routes (`apps/web/e2e/[locale]/(app)/planner/…`, `apps/web/e2e/api/…`). Every spec takes `test` and `expect` from `apps/web/e2e/fixtures.ts`, which sends the Cloudflare Access headers a pull-request preview requires to that preview's origin alone. The wiki has its own suite in `apps/docs/e2e/`. See [testing](/contributing/testing/).

## `patches/`

pnpm patches, listed under `patchedDependencies` in `pnpm-workspace.yaml`. The one patch today is for `vaul`, the drawer library; `apps/web/src/ui/modules/core/AGENTS.md` says what it changes and why.

## `apps/docs/`

This site. It has its own `package.json`, `astro.config.ts`, `wrangler.toml`, Playwright config and CI workflow (`.github/workflows/docs.yml`), shares the root Biome config, and imports app components from `apps/web/src/ui` through the `@ui` alias. See [how this wiki is built](/contributing/docs-site/).
