## Prerequisites

- **Node**: the exact version is pinned in `.nvmrc` (use `nvm use` / `fnm use`). CI reads the same file.
- **pnpm**: the exact version is pinned in the `packageManager` field of `package.json`; `corepack enable` picks it up automatically.

The repo is a pnpm workspace (`pnpm-workspace.yaml`): the app in `apps/web/` and this wiki in `apps/docs/`.

## Setup

```sh
pnpm install
```

Installing also runs the `prepare` script, which installs the husky git hooks (see [tooling](/contributing/tooling/)).

### Environment variables

- `apps/web/.env.example` lists the variables the app reads (Turso, Stripe, Resend, JWT, Better Stack, Google Analytics, the storage key and the site URL). Copy it to `apps/web/.env.development` and fill in your values.
- `apps/web/.dev.vars` holds the Worker-side secrets (the same keys) for wrangler. Both files are gitignored. `next.config.ts` calls `initOpenNextCloudflareForDev()`, which makes the Cloudflare bindings from `wrangler.toml` available during `next dev`, so `.dev.vars` matters even outside `pnpm preview`.

## Run it

```sh
pnpm dev                              # app on http://localhost:3000 (Turbopack)
pnpm --filter forever-pto-docs dev    # this wiki on http://localhost:4321
```

## Script cheatsheet

Every script below runs from the repository root; the root `package.json` is the source of truth.

| Script | What it does |
| --- | --- |
| `dev` | Next dev server with Turbopack |
| `build` / `start` | Production Next.js build / serve it locally |
| `preview` | OpenNext Cloudflare build + local workerd preview |
| `cf:build` | OpenNext Cloudflare build only, the build CI deploys; there is no app deploy script, see [workflows](/infra/workflows/) |
| `cf:typegen` | Generate `cloudflare-env.d.ts` from the wrangler config |
| `bones:build` / `bones:watch` | Generate skeleton components into `apps/web/src/ui/modules/bones` (boneyard-js, config in `boneyard.config.json`) |
| `format` / `format:changed` / `format:all` | Biome check with fixes (base / VCS-changed files / whole repo) |
| `lint` / `lint:changed` / `lint:all` / `lint:all:fix` | Biome lint (base / changed, with fixes / whole repo / whole repo, with fixes) |
| `format:check` | Biome check with no writes, the read-only gate `verify` runs |
| `typecheck` | The root program, then `apps/web`, then `astro check` over `apps/docs` |
| `typecheck:root` | The root program alone, one of the three typecheck steps CI runs in parallel |
| `test:ut` / `test:ut:coverage` | `apps/web`'s unit tests then the contract suite / with v8 coverage |
| `test:ut:changed` / `test:ut:watch` | `apps/web`'s unit tests over what changed / in watch mode |
| `test:docs` | The contract suite alone |
| `verify` | `format:check` + `typecheck` + `test:ut:coverage` in sequence; CI's `Verify` job runs the same scripts as parallel steps |
| `verify:changed` | `format:check` + `typecheck` + `test:ut:changed` + `test:docs`, what `pre-push` runs |
| `test:e2e` / `test:e2e:ui` | Playwright end-to-end tests / UI mode |

The docs package has its own scripts in `apps/docs/package.json`: `dev`, `build`, `preview`, `typecheck` and `test:e2e`. Neither package has a deploy script; both deploy from CI with an explicit `--env` (see [workflows](/infra/workflows/) and [docs CI](/infra/docs-ci/#production-deploy)).

:::note[Windows]
`cf:build` (the OpenNext Cloudflare build) fails on Windows, and so does `pnpm preview`, which runs it. Use WSL, or rely on CI: deploys run on Linux runners (see [environments](/infra/environments/)). `pnpm dev` is unaffected.
:::
