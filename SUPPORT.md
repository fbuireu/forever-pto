# Support

Forever PTO is maintained by one person. Everything below is best effort, and where you ask decides how fast
it gets looked at.

## If you use the planner

You do not need a GitHub account for any of this.

- **Something looks wrong in your plan**, or a public holiday is missing or falls on the wrong day: use the
  contact form in the app, or write to <contact@forever-pto.com>. Say which country and region you selected
  and which year you were planning: holidays are resolved per region, so the answer almost always depends on
  that pair.
- **A question about how the suggestions are built**: [docs.forever-pto.com](https://docs.forever-pto.com)
  explains the planner with the app's own components, so what you read there is what you are using.
- **Anything about a payment**: write to <contact@forever-pto.com>, never a public issue. Include the email you
  paid with and nothing else: no card details, and no payment link, which is a credential while it is live.

## If you are working on the code

- **A question, or an idea worth discussing before it is built**:
  [Discussions](https://github.com/fbuireu/forever-pto/discussions).
- **A reproducible bug**:
  [bug report](https://github.com/fbuireu/forever-pto/issues/new?template=bug_report.yml). The filters you had
  set (country, region, year, PTO days, carry-over) are what makes a planning bug reproducible, so start there.
- **A feature**: [feature request](https://github.com/fbuireu/forever-pto/issues/new?template=feature_request.yml).
- **Something wrong in the docs**:
  [documentation issue](https://github.com/fbuireu/forever-pto/issues/new?template=documentation.yml).
- **Before opening a pull request**: [CONTRIBUTING.md](./CONTRIBUTING.md).

## Vulnerabilities

Report privately through the [security policy](https://github.com/fbuireu/forever-pto/security/policy), never
as an issue or a discussion. [SECURITY.md](./SECURITY.md) states what is in scope and what to expect.
